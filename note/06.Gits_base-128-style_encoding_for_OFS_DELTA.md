# Git's base-128-style encoding for OFS_DELTA
## References
- Git commit **825cee7b285d9c733e9aec03cf4362e8029ee1c1** - See Git [repository](https://github.com/git/git).
- [pack format](https://git-scm.com/docs/pack-format.html)

## The main part of this note.

in builtin-pack-objects.c, you see the following in write_object() and check_object()

in write_object()
```
		if (obj_type == OBJ_OFS_DELTA) {
			/*
			 * Deltas with relative base contain an additional
			 * encoding of the relative offset for the delta
			 * base from this object's position in the pack.
			 */
			unsigned long ofs = entry->offset - entry->delta->offset;
			unsigned pos = sizeof(header) - 1;
			header[pos] = ofs & 127;
			while (ofs >>= 7)
				header[--pos] = 128 | (--ofs & 127);
			sha1write(f, header + pos, sizeof(header) - pos);
			hdrlen += sizeof(header) - pos;
		}
```

in check_object()
```
			case OBJ_OFS_DELTA:
				c = buf[used++];
				ofs = c & 127;
				while (c & 128) {
					ofs += 1;
					if (!ofs || ofs & ~(~0UL >> 7))
						die("delta base offset overflow in pack for %s",
						    sha1_to_hex(entry->sha1));
					c = buf[used++];
					ofs = (ofs << 7) + (c & 127);
				}
				if (ofs >= entry->in_pack_offset)
					die("delta base offset out of bound for %s",
					    sha1_to_hex(entry->sha1));
				ofs = entry->in_pack_offset - ofs;
				base_name = find_packed_object_name(p, ofs);
				break;
```

So, the encoder (write_object()) does,
```
			header[pos] = ofs & 127;
			while (ofs >>= 7)
				header[--pos] = 128 | (--ofs & 127);
```
, and the decoder (check_object()) does,
```
				ofs = c & 127;
				while (c & 128) {
					ofs += 1;
					...
```

I was pullzed why Git does `--ofs` during encoding, and does `ofs += 1` during decoding.

### The reason why. (my assumption)

(* note) **ofs** = An offset indicating how many bytes to go back to reach the base object.
(check the following comment in write_object().)
```
Deltas with relative base contain an additional
encoding of the relative offset for the delta
base from this object's position in the pack.
```
ex.)
if
```
base object       offset = 1000
current object    offset = 1500
```
then,
```
ofs = 1500 - 1000
    = 500
```

Now, let's start encording with ofs = 255 (```11111111```), 
we get
```
255 & 127
= 1
```
by
```
header[pos] = ofs & 127;
```
then,
```
while (ofs >>= 7)
```
implies
```
ofs = 11111111 >> 7
    = 1
```
and since ```while (1)``` is true, the process goes into the loop.

Here, ```--ofs``` is done, e.g. ```1``` $$\rightarrow$$ ```0```.

Then, by calculating
```
(--ofs & 127)
```
for ```ofs == 1```, we get
```
0 & 127 (0 & 1111111)
= 0
```
Then, 
```
header[--pos] = 128 | 0;
```
results
```
128 | 0 (1000 0000 | 0 -> 1000 0000)
= 128
= 0x80
```
Therefore
```255``` $$\rightarrow$$ ```80 7f (1 0000000 | 0 1111111)```.

Here, ```80 7f``` is
```
1 000 0000
0 111 1111
```
The first ```80``` implies
```
continuous bit (leftmost bit) -> 1
data -> 000 0000
```
the second ```7f``` implies
```
continuous bit -> 0 (not continuous)
data -> 111 1111
```

Now, when decoding ```80 7f```, 
the data in buf will be,
```
buf[0] = 80
buf[1] = 7f
```

```
c = buf[used++];
ofs = c & 127;
while (c & 128) {
	ofs += 1;
	if (!ofs || ofs & ~(~0UL >> 7))
		die("delta base offset overflow in pack for %s",
		    sha1_to_hex(entry->sha1));
	c = buf[used++];
	ofs = (ofs << 7) + (c & 127);
}
```
by the data of buf and code above,

the initial ```c``` was ```80``` and the initial ```ofs = 0``` by  ```c & 127 (1 000 0000 & 111 1111 = 0)```.

Since ```c & 128``` is ```1 (1 000 0000 & 1 000 0000)``` at ```while (c & 128)```, the process goes into the while loop.

Then, 

ofs becomes ```1``` because of ```ofs += 1```.

c's value is taken from buf[1] and it becomes ```7f (127)```.

then, ofs becomes ```(1 x 128) + 127 = 255``` from ```ofs = (ofs << 7) + (c & 127);```

since ```<<7``` means ```x 128``` and ```127 & 127 (111 1111 & 111 1111) = 127```.

We were able to decode it correctly and obtain the correct value of ```255```.


### Now, what if we don't do ```--ofs``` and ```ofs += 1```?
Let's say the data was ```80 7f``` and we handle this data as ```big-endian base-128``` fashion.

Then, ```80 7f``` will be decoded by ```big-endian base-128``` to,
```
0 × 128 + 127
= 127
```
i.e.

```80``` will be considers as ```0```
because
```
continuous bit (leftmost bit) -> 1
data -> 000 0000
```
and ```7f``` is ```127```

which is different from the original value ```255```.
